前端项目组合内容蓝图

0三者的关系：先定架构再动手

不要做成三个独立仓库，共用一套底座，工程体量和说服力都翻倍

① 业务中台
进销存主链路、单据状态机、权限、复杂表单表格。工作量占比约 55%
② AI 智能模块
内嵌在中后台右侧助手栏，复用登录态与业务接口。占比约 20%
③ BI 决策大屏
独立路由 /bigscreen，同时作为中后台首页看板。占比约 25%
统一底座（三个入口共用，千万别各写一套）
用户与登录态 · RBAC 权限 · 数据字典 · 请求层封装 · 通用业务组件 · 主题与 CSS 变量 · 接口约定
业务域建议选「智能仓储 / 进销存」。理由有三：一是信管的 ERP、数据库课程天然对口，业务流程图和 ER 图可以一起放进简历； 二是它同时需要大屏（库存周转、出入库趋势）和 AI（智能补货、异常解读），三个模块是互相喂数据的，不是硬凑； 三是比「博客后台」「图书管理」高一个档次，面试官一听就知道有真实流程。

1业务中台：企业中后台管理系统

决定下限的模块，权限和动态路由是必须啃下来的两块硬骨头

权限与账户体系

  • RBAC 五表模型用户 / 角色 / 权限 / 用户角色 / 角色权限；权限分菜单、按钮、接口三类必做
  • JWT 双 Token 无感刷新access 过期后用 refresh 换新，axios 响应拦截器挂起失败请求并重放，用户零感知必做亮点
  • 后端驱动动态路由接口返回路由树，前端 import.meta.glob 映射组件，router.addRoute 动态注册必做亮点
  • 按钮级权限v-permission 自定义指令 + usePermission 组合式函数双通道必做
  • 数据级权限仓管只看所属仓库的数据，靠数据范围字段过滤，解决「权限只能到页面」的通病加分

业务主链路（进销存）

  • 基础数据商品、供应商、客户、仓库、库位、计量单位、数据字典必做
  • 采购流程采购申请 → 采购订单 → 到货验收 → 入库单必做
  • 销售流程销售订单 → 出库拣货 → 发货 → 回单确认必做
  • 库存管理库存台账、批次与效期、库位调拨、库存锁定与释放必做
  • 盘点管理盘点单生成 → 实盘录入 → 盘盈盘亏处理 → 库存调整入账必做亮点
  • 单据状态机草稿 → 待审 → 已审 → 执行中 → 完成 / 作废，状态驱动按钮显隐与操作权限。业务系统的灵魂，一定要做必做亮点
  • 库存预警规则安全库存下限、临期预警，阈值可配置并推送到大屏与 AI 模块加分

复杂表单与表格（前端硬技能主战场）

  • 主子表单据编辑单据头 + 明细行，行内编辑、金额联动计算、批量增删、校验定位到行必做亮点
  • 可配置表格列显隐、列拖拽排序、列宽调整，配置持久化到 localStorage必做
  • 十万行虚拟滚动自研或 @tanstack/vue-virtual，滚动稳定 55fps 以上，必须有前后对比数据必做亮点
  • Excel 导入导出SheetJS，导入做字段校验并把错误行标红回显，导出支持合并表头必做
  • 附件与图片上传分片上传、断点续传、进度条、失败重试加分
  • 单据打印@media print 样式或 lodop 打印控件加分

通用能力封装（面试最能聊的部分）

  • 请求层封装统一错误码映射、重复请求取消、loading 计数、超时重试、取消信号必做
  • 组合式函数库useTable / useFormModal / useDict / useExport / useSSE / useWebSocket必做亮点
  • 通用业务组件字典选择器、组织树、用户选择器、地区级联、日期区间、状态标签必做
  • 多标签页与缓存keep-alive + 标签栏，支持刷新、关闭其他、右键菜单加分
  • 主题与国际化暗色模式、主色切换；vue-i18n 中英文切换加分

工程化与上线闭环

  • 代码规范ESLint + Prettier + Husky + lint-staged + commitlint必做
  • 自动化测试Vitest 覆盖工具函数与 hooks，Playwright 跑 2-3 条关键业务流 E2E加分亮点
  • CI/CDGitHub Actions：push 触发 lint + test + build，产物自动部署必做
  • 部署Nginx 静态托管 + gzip + 强缓存策略，dev / staging / prod 三套环境变量必做
  • 文档README + 部署文档 + 接口约定，VitePress 搭一个项目文档站加分

2AI 智能模块：内嵌进中后台

2026 年最值钱的一栏，但含金量取决于「有没有和业务打通」，光做个聊天框等于没做

基础对话能力

  • SSE 流式输出fetch + ReadableStream 手动解析 SSE（比 WebSocket 更简单也更主流），打字机渲染必做亮点
  • 中断与重试AbortController 停止生成、重新生成、失败重试、错误兜底提示必做
  • Markdown 渲染markdown-it + 代码高亮 + 一键复制 + 表格与链接样式适配必做
  • 会话管理多会话列表、重命名、删除、历史持久化、会话上下文隔离必做
  • 上下文窗口管理超过 N 轮做摘要压缩、token 估算、系统提示词固定占位亮点
  • 模型接入抽象层统一适配 OpenAI / DeepSeek / 通义 / 本地 Ollama，配置化切换加分

业务融合（决定这一栏值不值钱）

  • 自然语言查数据Function Calling 让模型输出结构化查询条件（不是直接拼 SQL），前端拿到结果自动渲染成表格并自动选图表类型必做亮点
  • 智能填单粘贴一段文本或上传单据，AI 抽取字段自动填充表单，支持人工校正后再提交必做亮点
  • 预警解读对库存预警列表生成自然语言摘要，给出建议补货量与安全库存调整意见加分
  • 报表异动解读点击大屏任一指标，AI 解释同比环比异动原因，与大屏联动加分
  • 前端容错与成本首 token 耗时展示、超时降级、相同问题结果缓存、敏感字段脱敏必做
提醒：不要训练模型、不要做 RAG 向量库这些重活，那不是前端的考点。你的考点是「把模型能力接进业务界面」—— 流式体验、结构化输出、结果可视化、异常兜底。把这四个做扎实，比搭个复杂 RAG 有用得多。

3BI 决策大屏

信管的运筹学、统计学课程在这里变现，指标口径比图表特效更重要

布局与适配

  • 多分辨率适配1920×1080 设计基准适配到 4K；transform scale 等比缩放 或 rem + vw 二选一，把选型理由写进 README必做亮点
  • 栅格 / 布局引擎24 栅格或分区块布局，支持区块显隐与顺序配置必做
  • 统一主题暗色科技风，ECharts registerTheme + CSS 变量统一色板必做

图表内容（至少 8 个）

  • ① 核心指标卡今日出库量、库存周转率、缺货 SKU 数、订单履约率，带同比环比 + 数字滚动动画必做
  • ② 出入库趋势双轴折线 / 面积图，支持日 / 周 / 月粒度切换必做
  • ③ 库存结构按品类的环形图 + 玫瑰图必做
  • ④ TOP10 排行供应商 / 客户横向条形图，超出可视区自动轮播滚动必做
  • ⑤ 库位热力图heatmap 展示仓库—库区的库存密度，识别拥堵库区亮点
  • ⑥ 实时单据流水WebSocket 推送新单据，滚动列表 + 新条目高亮动画必做亮点
  • ⑦ 预警中心仪表盘 gauge + 缺货与临期预警滚动列表，可点击下钻必做
  • ⑧ 区域业务分布省级分布。注意地图数据合规：优先用条形图或经核验的地图数据，避免踩合规红线加分

性能与体验

  • 增量更新WebSocket 推送后走 setOption 增量合并，不做整图重绘亮点
  • Web Worker大数据聚合计算挪到后台线程，主线程不掉帧亮点
  • 生命周期管理ResizeObserver 自适应；组件卸载销毁 ECharts 实例，防内存泄漏必做
  • 离屏优化visibilitychange 暂停动画与轮询，页面不可见时不渲染加分
  • 三态处理加载骨架屏 / 空数据 / 请求异常，各自有明确呈现必做

图表配置化（拉高档次的一招）

  • 配置驱动渲染一份 JSON 描述图表类型、数据源、样式，引擎统一渲染，新增图表零改代码亮点
  • 与 AI 模块打通AI 自然语言查询的结果直接生成图表配置，交给同一套渲染引擎出图亮点

5简历上怎么呈现

建议写成一个项目的三段，而不是三个项目——三个都写会显得每个都浅

智联仓储管理系统（SmartWMS）
Vue 3 + TypeScript + Vite + Pinia + Element Plus + ECharts · 独立开发 · [GitHub] [在线预览]

业务中台：面向中小仓储企业的进销存管理系统，覆盖采购、入库、出库、盘点全链路。设计基于 RBAC 的五表权限模型，实现后端驱动的动态路由与按钮级权限指令；抽象单据状态机驱动 5 类单据流转，主子表编辑与 10 万行虚拟滚动将库存明细页滚动帧率稳定在 55fps，首屏 LCP 由 3.2s 优化至 1.4s。

AI 智能模块：基于 SSE 实现流式对话（首 token 响应 < 800ms），通过 Function Calling 将自然语言转为结构化查询条件，结果由前端自动渲染为表格与图表，覆盖常见库存查询场景；实现会话上下文摘要压缩与多模型接入抽象层。

决策大屏：面向管理层的库存决策看板，按库存周转率、订单履约率等运营管理指标设计指标口径；采用配置驱动渲染引擎，8 类图表由 JSON 配置生成；WebSocket 增量推送 + Web Worker 数据聚合，支持 1920 至 4K 多分辨率自适应。

备选拆法（时间不够时）：拆成两个项目——「智联仓储管理系统（含 AI 智能模块）」和「仓储数据可视化大屏」。 前者体现工程深度与业务理解，后者体现可视化专项，投递可视化方向的岗位时更精准。但不要拆成三个。

6范围控制：明确不做的

做不完是这套方案最大的风险，以下一律留到面试聊，不写进代码

  • 不做真实支付与物流对接用 mock 数据模拟即可，简历写「模拟对接」
  • 不自建 RAG 向量库与模型训练调用现成模型 API 足够，前端考点不在这
  • 不做移动端 App中后台用响应式适配即可，不要开新战线
  • 不做微服务与复杂的后端架构用 Node 或 FastAPI 写够用的接口，精力留给前端
  • 不做权限以外的「系统设置」周边日志审计、消息中心等留作 TODO 写在 README 里，反而是加分项
